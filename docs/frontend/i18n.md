# Translations (French / English)

[Up: Frontend guide](README.md) · [Backend guide](../backend/README.md)

The UI is French by default and English on request. English is the source language of
every template and `$localize` string; French is loaded at runtime.

## How the language is chosen

- [`locale.ts`](../../frontend/src/app/core/i18n/locale.ts) reads the `locale` key from
  `localStorage` (`fr` or `en`, default `fr`).
- The FR / EN switch ([`language-switch`](../../frontend/src/app/shared/language-switch/language-switch.component.ts))
  stores the choice and reloads the page, because translations are registered once.
- The [`translations.ts`](../../frontend/src/translations.ts) polyfill entry
  (`angular.json`) bundles `src/locale/fr.json` and calls `loadTranslations` for
  French before any application module evaluates `$localize`. Polyfills run before
  `main.ts`, which then imports and bootstraps the application statically, so the
  whole startup set is hashed, preloaded in parallel, and cached by the browser.
  English visitors download the French table too (about 12 kB compressed).
- [`locale.interceptor.ts`](../../frontend/src/app/core/interceptors/locale.interceptor.ts)
  sends `Accept-Language` on every API request.

## Marking text

- Templates: `i18n` on elements and `i18n-<attr>` on static attributes.
- Attributes containing interpolation (`aria-label="Remove {{ name }}"`) must not use
  `i18n-aria-label`: Angular turns them into a property binding that does not exist on
  the DOM element, so the label disappears. Bind `[attr.aria-label]` to a component
  method returning `` $localize`Remove ${name}:name:` `` instead.
- TypeScript: `` $localize`…` ``, with named placeholders (`${value}:name:`) when the
  text has variables.
- Never display raw server text that is not translated. REST errors arrive translated
  (see below); WebSocket `ERROR` events and STOMP error frames are mapped by `code` on
  the client.

## Updating translations

```bash
cd frontend
npm run i18n
```

The script extracts messages to `src/locale/messages.json` and builds
`src/locale/fr.json` from the English→French table in
`src/locale/fr-translations.json`. It fails on any message without French text or with
mismatched placeholders, so add the missing entries to the table and run it again.
Commit all three files.

Unit and Playwright tests run in English: the Playwright configurations store
`locale=en`, and `e2e/i18n.spec.ts` covers the French default and the switch.

## Backend

The backend resolves the request language from `Accept-Language` (French by default,
[`LocaleConfig`](../../backend/src/main/java/com/blindtest/config/LocaleConfig.java)).

- Emails: `backend/src/main/resources/i18n/emails*.properties`.
- REST error `message`: `i18n/errors_fr.properties`, keyed `error.<ApiErrorCode>`; the
  English text in [`ApiErrorCode`](../../backend/src/main/java/com/blindtest/error/ApiErrorCode.java)
  is the fallback. Add a French line whenever a code is added.
- The `code` field stays stable and is what clients should branch on.
